Versions Panel Redesign

The current panel lists version number, uploader and date, and offers Download and Delete on every row. It cannot say which version is live, what changed between versions, whether a version is still usable, or that a public URL is serving one of them. This redesign adds those four things and removes the action that makes an asset disappear.

Build: VersionCard · EditFile versions tab Depends on SCR-338, SCR-339, SCR-343, SCR-344, SCR-350 Target: Cycle 10

Current is visible

A 2px accent edge and a Current badge on the live version. Everything below it is history, dimmed but readable.

Rows carry a file

Thumbnail, size, dimensions and format, so you can tell versions apart without downloading them.

Public links are in the panel

One line at the top says how many links exist and which version they serve, with a retry when a refresh fails.

Actions match authority

Delete leaves the current row. Make current appears for the roles allowed to publish. Download disables with a reason.

Open on this design

  1. Does the row need a change note? A one-line "what changed" field would make the history readable a year later, but it is a new field on upload and nobody has asked for it. Left out for now.
  2. Where does Withdraw live? Shown here as a row action. It may belong in Rights instead, since it is a rights decision rather than a version one.
  3. Thumbnail for non-image assets. The filetype badge carries the format, but a PDF or PSD row needs a defined placeholder rather than a blank tile.
  4. Does the public-link line belong here or in Rights? It is shown in Versions because a version bump is what changes what the link serves, and this is where people will look after uploading.
