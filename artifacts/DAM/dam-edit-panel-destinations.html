What each edit destination actually needs

The panel width holds constant across all seven rail tabs, so it has to be sized to the widest one. This page renders the densest row from each destination at a width you control and reports which ones break. Nothing here is asserted: the wrap detection measures the real rendered rows.

Revised 15 Sep against the Attributes capture. Attributes is a faceted checkbox list, not label and input pairs, which is a different structure from what the first version of this page assumed. It turns out to be the destination with the lowest width need, not a beneficiary of extra width, and its real problem is height. Section 03 is rewritten accordingly.

03

What width does and does not buy Attributes

Attributes is a faceted checkbox list: fifteen groups, each expanding to its values. Official Mark alone holds 53. The longest real value in the FIFA schema, Official Hospitality Logo, renders at 152 px inside a row that already has 209 px at today's width. So the panel is not width-starved here. Extra width lands as dead space to the right of every checkbox.

The one thing width can buy is a second column in the value list, which halves the height of every long group. Below, the same twenty Official Mark values in one column and in a responsive grid, both at the current panel width.

The cheaper fix is a conformance fix. The contract specifies Attributes at parity with library filters: an active-group edge plus an n of total count on the header. Neither is in the build. Without the count, a collapsed group tells you nothing about whether it holds selections, so the only way to check is to open it, which is exactly the all-groups-expanded state in the capture. Restoring the count pill removes the reason to expand and buys back more height than any amount of width. Do that before reaching for columns.

04

How the band was derived

  • Floor is 400, set by RightsThe territory picker holds a chip row of ISO country names above the picker list. Country names run long, and a chip row that can only hold one chip per line turns a carve-out with six territories into a six-line block. 400 is the point where three of the longest names fit across two lines rather than six.
  • Ceiling is 520, set by Versions and AdjustmentsA version row carries thumbnail, version, actor, timestamp and status, and needs the actor and timestamp on one line to stay scannable. Adjustments sliders are monotonically better with width until the track stops being the constraint. Past 520 neither improves and key and value rows get worse, because the value column just stretches.
  • Sized to the widest, not the averageA panel that changes width on tab change reflows the canvas every time you move between Attributes and Rights. Predictability before novelty: pick one width, let the narrow destinations sit inside it.
  • The percentage is 24%, not a fixed numberBetween the floor and the ceiling the panel tracks the surface, so a 27" monitor gets a usefully wider panel without a preference to set. Outside that range the clamp pins it. On a 1280 laptop you are at the floor, on anything above about 2170 you are at the ceiling.
  • Attributes does not voteIt is the narrowest destination in the panel and it tolerates whatever the others need. Its longest real value is 152 px in a 209 px row, so it has headroom today and gains only dead space from more. The band rests on three destinations: Rights, Versions and Adjustments. That is narrower evidence than seven, and worth saying out loud.
  • What is not solved by widthFifteen groups, one of them holding 53 values, is a height problem with three separate fixes and only one of them is width. In order of cost: restore the missing count pill so groups do not need opening, keep the existing show-more truncation, and only then consider a second column in long value lists. Reaching for width first solves the cheapest third of the problem at the highest price.
