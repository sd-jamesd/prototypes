Row 1 is a chromatic family. Row 2 is Gray at step 12, a deliberate choice meaning uncategorised. Row 3 is disabled. The three should read as three different things.

Greyscale changes nothing here, which is the point: this pair was never distinguished by hue, only by contrast.

The rule this establishes. Disabled is signalled by contrast, not by hue. A live state never renders below roughly 5:1 and disabled never renders above roughly 3.5:1. That gap is the whole signal, and it holds for chips, buttons, rows and inputs, not only badges. The nine chromatic families keep step 11 because they are told apart from disabled by hue, a channel disabled does not use.
What this does not fix. Grey still means uncategorised. If config picks Gray for a live workflow step it will read as "no category chosen" even at 14.30:1. That is guidance for config, not a token problem.
